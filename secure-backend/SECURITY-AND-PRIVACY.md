# 數學任務站：資安與個資保護上線基準

這套後端把身分、權限、班級關係、報告與稽核紀錄移到伺服器。瀏覽器中的角色文字或 localStorage 不再是授權依據。這是技術控制基準，不等同主管機關或律師的合規認證；正式處理未成年學生資料前，學校仍須完成個資盤點、風險評估、告知文件及委外契約審查。

## 已實作的控制

- 六位數驗證碼使用密碼學安全亂數，伺服器只保存 HMAC 摘要；10 分鐘到期、最多錯 5 次、同帳號與來源每小時最多寄送 5 次。
- 工作階段使用不可預測權杖；資料庫只保存摘要；Cookie 為 HttpOnly、SameSite=Strict，正式環境另強制 Secure。
- 修改資料需同源檢查與 CSRF 權杖；回應加入 CSP、禁止嵌入、MIME 防護、權限政策、HSTS（正式環境）。
- 學生只可存取自己的作業與報告；教師只能存取開發者指派班級；開發者可審核與指派，但所有敏感操作留下防竄改雜湊鏈稽核紀錄。
- 龍門學生帳號格式由伺服器解析，自動歸入 701–720、801–820、901–920 與座號 01–40。其他使用者須先完成信箱驗證與申請，再由開發者核准。
- 報告及稽核資料有保存期限；提供個資查詢、複製、更正、限制與刪除請求入口；清除工作可由排程呼叫 `/api/admin/purge`。
- 信箱以 HMAC 查找值加 AES-256-GCM 密文保存；學習報告、申請身分、任職單位、職稱、姓名與組織欄位使用獨立資料加密金鑰保護。正式主機仍須使用加密磁碟及加密備份。
- 教師／開發者後台只呼叫安全 API，角色與資料範圍完全由伺服器 Session 及班級關係決定，不讀取 localStorage 作為權限依據。
- 錯誤回應不洩漏堆疊、驗證碼或密鑰，稽核 metadata 會排除敏感欄位。

## 正式上線前必做

1. 只能由反向代理的 HTTPS 對外，後端維持 `127.0.0.1`；開啟 TLS 1.2/1.3，設定自動憑證更新。
2. 使用 `.env.example` 建立主機端祕密設定；兩把密鑰須各自至少 64 字元、不可放進 Git、文件或前端。
3. 資料庫放在加密磁碟或加密雲端磁碟，檔案權限只給服務帳號；每日加密備份，定期做還原演練。大量正式使用建議改採受管 PostgreSQL，並維持相同的列級權限規則。
4. 郵件服務使用學校核准供應商；API 金鑰只存祕密管理服務。不得在正式畫面顯示驗證碼。
5. 不得重新啟用舊版 `auth.js`、`role-access.js` 或任何以 localStorage 判斷角色的程式；GitHub Pages 版固定為匿名練習。
6. 依 `privacy.html` 的個資告知內容補上正式合作學校、承辦窗口、代管商、資料地區及未成年人適用法源，並由校方核准後才啟用真實學生資料。
7. 委外代管、郵件及 AI 服務須在契約中限制目的、資料所在地、再委外、刪除/返還、稽核與事件通報。不要把學生姓名、信箱、完整作答直接送給公開 AI 服務。
8. 指定事件聯絡人，演練帳號停用、權杖失效、日誌保存、影響範圍判定及通知；依法規與主管機關要求處理事故。
9. 上線前由獨立人員進行弱點掃描與滲透測試，上線後固定更新 Node 與作業系統，至少每季複核教師班級權限。

## 啟動

學生及申請者驗證碼只會透過已核准的郵件服務寄到本人信箱，不會出現在 HTTP 回應、網頁、網址、瀏覽器紀錄或後端終端機。未設定郵件服務時，系統會拒絕寄送並顯示服務尚未設定。正式啟動必須設定 `NODE_ENV=production` 與 `.env.example` 中的必要值，再執行：

`node secure-backend/server.mjs`

健康檢查為 `GET /api/health`，只回覆服務狀態，不回傳資料庫、版本或環境資訊。

## 維運與通報流程

- 偵測異常後先保存證據、撤銷工作階段與金鑰、隔離受影響服務，再判定資料種類、人數、時間及影響。
- 通知內容不得夾帶更多個資；紀錄發現時間、處置、通知與改善措施。
- 每月檢查待處理個資權利請求與過期資料；每季驗證備份可還原、稽核雜湊鏈連續、教師僅看見本人班級。
- 離職或調班當日撤銷教師指派與所有工作階段；學生畢業後依公告保存期限刪除或去識別化。
